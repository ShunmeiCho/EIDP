# EIDP v1.1 Charter — Rolling Target Fiscal Year System

Status: charter (pre-sprint, owner sign-off pending)
Date: 2026-05-06
Branch base: sprint8-handoff-finalize @ 7185787

## Why this charter exists

Sprint 8 delivered a Windows-deployable PDF discovery + operator console.
Two owner reviews on 2026-05-06 found that the **product center is wrong**
even though the technical scaffold is sound:

1. The system was framed as a "PDF review tool" — its main loop optimises
   for "did we collect any application form?", not for "did each school's
   target-fiscal-year status advance this week?".
2. R8 / 令和8 leaked into file names, paths, runbooks, and operator UI
   labels even though the runtime variable `target_fiscal_year` is
   already configurable. Next year's R9 rollover would require
   maintenance work that the design promised would be a one-line config
   change.
3. Strict mode landed in pdf_discovery (sprint 8.7.f), but the surrounding
   queues, dashboards, and Excel exporter still treat any-fiscal-year
   PDFs as "progress" so 80 R7/R6 PDFs visually pose as success while
   FY2026 = 0 schools is the real release blocker.

This charter is the agreed list of work that converts EIDP from
"FY2026-specific deployment" to "rolling target-fiscal-year acquisition
system covering 専門学校 end-to-end today, with only a gated 大学 pilot
before full 大学 rollout in v1.2".

## Scope contract

### v1.1 covers
- 専門学校 (about 1,700 schools) end-to-end automated acquisition
- optional 10-school 大学 pilot only after R-3/R-4 have stabilized
- target_fiscal_year-driven UI, exporter, and weekly runner
- Discovery layered through prefecture aggregator → school site → operator
  override (firecrawl / sitemap / Playwright explicitly deferred to v1.2)
- Year-evidence ladder for fiscal-year decisions
- Rolling rename so FY2027 / 令和9 ships with one config change

### v1.1 explicitly excludes
- full 大学 rollout (about 700 schools) — separate parser + discovery track
  scales in v1.2 after the gated pilot
- Firecrawl / search-engine API discovery
- Playwright JS rendering
- OCR add-on second pass (already an optional ZIP today)

### Acceptance criteria
- All operator-facing copy says `2026年度（令和8年度）` form, never bare R8
- File names / paths / module names contain `target_year` or
  `weekly_discovery`, never `r8`
- Excel exporter for business use is locked to settings.target_fiscal_year
- 学校別タスク page is the new home page; PDF確認 is a detail panel
- Year decisions carry an evidence_level field (filename / pdf_text /
  prev_year_diff / download_time) and `download_time` cannot escalate to
  `confirmed_target`
- Existing 8.x audit log entries with action_type = "r8_override" remain
  readable; new writes use "fiscal_year_override"

### Phase R-2: SchoolFiscalYearStatus model + view (P0, 3-5 days)

Replace the implicit "search Document table" pattern with an explicit
School × FY status row that aggregates everything an operator needs.

Schema (new table):
```
school_fiscal_year_status (
  school_id INT,
  fiscal_year INT,
  url_status ENUM(unknown / pref_url / operator_url / no_url),
  pdf_status ENUM(none / discovered / confirmed_target / rejected_stale
                  / duplicate_other_school / image_pending),
  extract_status ENUM(none / parsed / parse_failed / ocr_pending
                      / manual_entered),
  yoy_diff_status ENUM(unchecked / identical_to_prev_fy
                       / partial_diff / major_diff / new_school),
  excel_ready BOOLEAN,
  blocking_reason TEXT,
  evidence_level ENUM(none / filename / url_hint / pdf_text
                      / prev_year_diff),
  updated_at TIMESTAMP,
  PRIMARY KEY (school_id, fiscal_year)
)
```

Writer hooks:
- `discover-pdfs` updates `url_status` + `pdf_status` + `evidence_level`
- `ingest-pdfs` updates `extract_status` + `excel_ready`
- `fiscal_year_override` updates `yoy_diff_status` + `evidence_level`
- `manual_entry` updates `extract_status` + `manual_entered`

Acceptance:
- View row count = active 専門学校 count for current target FY
- Each row's `excel_ready` flips True only when `extract_status=parsed`
  AND `pdf_status=confirmed_target`
  AND `evidence_level` IN (pdf_text, prev_year_diff)
  AND `yoy_diff_status` IN (unchecked, partial_diff, new_school) — never
  `identical_to_prev_fy`

- ③ Excel 出力前に gap report 表示、空状態でも警告のみ

### Phase R-4: Year evidence ladder (P0/P1, 5-7 days)

Year decision becomes a graded ladder, not a boolean. The download_time
fallback in `pipeline/ingest.py:255` is downgraded to a hint only, never
the sole basis for `confirmed_target`.

Evidence levels (low → high):
```
0 none           — no signal at all
1 filename       — URL/anchor contains 令和N年度 / FY YYYY token
2 url_hint       — server-supplied date or path year
3 pdf_text       — extracted body text matched 令和N年度 / YYYY年度 form
4 prev_year_diff — at least one DepartmentYearly value diverges from
                   prev FY (so the PDF cannot be a re-publication)
```

Rules:
- `confirmed_target` requires evidence_level >= 3
- `evidence_level == 4` upgrades automatically when ingest detects
  any non-trivial diff from previous year
- if extracted PDF text explicitly confirms a non-target fiscal year,
  `prev_year_diff` routes to operator review instead of auto-confirming
- `download_time` never escalates evidence_level above 1
- New `manual_action_log.action_type = "fiscal_year_evidence_promote"`
  for operator-driven upgrades

Files:
- `src/eidp/scraper/pdf_discovery.py` — write evidence_level on download
- `src/eidp/pipeline/ingest.py` — evaluate prev-year diff and upgrade
- `src/eidp/pipeline/fiscal_year_override.py` — evidence_level=user
  for human-confirmed fiscal year

### Phase R-5: 学科変更 productisation (P1, 3-5 days)

Today major school changes (新設 / 廃科 / 名称変更 / 統合) are mixed
into the regular numeric review queue. Owner baseline (2026-04-27)
shows this masks data integrity issues.

Make `DepartmentChange` a first-class review type:
- New page section: `学科変更要確認`
- Detection: `matcher/reconciler.py` already produces candidates;
  pipe them into the new `DepartmentChange` review type instead of
  generic `review_pending`
- UI affords explicit decisions: 新設 / 廃科 / 名称変更 / 統合 / 誤検出

### Phase R-6: Discovery layered fallback (P1, 5-7 days)

Layer the discovery chain so missing-URL schools get progressively
broader treatment without firing all crawlers blindly.

```
Layer 1 prefecture aggregator    <- today
Layer 2 school site sitemap.xml  <- new
Layer 3 school site search       <- new (best-effort HTTP search)
Layer 4 corporation HP           <- new
Layer 5 operator manual URL      <- already exists
```

Each layer writes its method into `school_site.discovery_method` so
analytics can show the funnel. Firecrawl + Playwright are still
v1.2 because they need external API keys / Chromium binary.

### Phase R-7: 大学 pilot (P1, 5-7 days)

Produce a 10-school 大学 parser + discovery pilot running alongside
専門学校 but gated by `school_type == "大学"`. School-code source is MEXT
(`data/mext/target_institutions.xlsx`). UI / weekly runner are aware
of both school types, but full 700-school rollout stays v1.2.

Owner sign-off before scaling 大学 from 10-school pilot to full 700.
