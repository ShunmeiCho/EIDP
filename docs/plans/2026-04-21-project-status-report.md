# EIDP 项目进展报告

**日期**: 2026年4月21日
**项目**: Education Institution Data Pipeline (教育机关在籍数据自动采集系统)
**目标交付日**: 2026年6月

---

## 1. 项目目标

自动化收集约 2,400 所日本专门学校的在籍学生数据。数据来源：各学校在官网公开的 **高等教育修学支援新制度 機関要件確認申請書（様式第2号）** PDF 文件。替代目前 6-8 月期间由人工手动下载、阅读、录入 Excel 的流程。

**成功标准**: 减少人工工作量 50-70%。

## 4. 当前遇到的关键问题

### 4.1 🔴 最大瓶颈：PDF 自动发现天花板

**问题**: 在 1,827 所有 URL 的学校中，自动爬虫只能发现 87 个有效 PDF（4.8%）。盲目爬取 8 分钟 0 收益。

**根因**:
1. Target PDF 多数位于 `/wp-content/uploads/...` 深度 3+ 目录，爬虫天然难发现
2. 部分大法人（如大原学园 182 校、三幸学园 100 校）**可能根本不公开** 様式第2号，或公开在法人级而非学校级
3. 每所学校发布位置、文件命名模式差异大，无法通用规则推断

**去年人工团队上限**: 完全采录 943 所（45.6%）、部分采录 804 所。**人工也有上限**，不是所有学校都会公开。

### 4.2 🟡 OCR 解析成功率 23%

**问题**: 87 个成功下载的 PDF 中，只有 20 个完整解析入库。

**失败分类**:
- parse_failed: 16 个（非标准表单、或页面结构异常）
- school_mismatch: 12 个（PDF 与学校不匹配，多为法人共享 PDF）

### 4.3 🟡 缺乏人工知识传递渠道

**问题**: 用户团队过去采录的 943 所学校的 URL 知识（文件位置模式）没有录入系统。

**影响**: AI 只能盲目爬取，无法利用人类积累的定位经验。

### 4.4 🟢 待办架构工作

- 没有 setup.sh 一键部署脚本（交付给学校 IT 困难）
- 没有 cron 自动化（每周更新需要人工）
- 没有回归测试覆盖 OCR 流程
- 323 所 reconcile 候选需人工确认（大原 52 + 三幸 30 等）

## 6. 下一步建议（三条路径，并行推进）

### Path A: 定向深度爬取（如果用户能提供去年 URL）

**工作量**: 1 天
**预期效果**: 500-800 所学校覆盖

策略：用去年 URL 作为锚点，预测今年路径（year replacement / parent directory listing / fallback crawl）。比盲目全站爬取效率高 30-100x。

### Path B: 接受现状，优化交付

**工作量**: 3-5 天
**内容**:
- 编写 setup.sh + README（学校 IT 一键部署）
- 设置 weekly cron（每周增量更新）
- 完善人工介入流程（review UI + 手动上传 PDF）
- 编写回归测试

**产出**: 可交付 MVP，24 所学校有最新 2025 数据 + 2,068 所有 2024 历史数据。

### Path C: 人机混合（推荐）

**工作量**: 1-2 周
**内容**:
- Streamlit review UI 加 PDF 上传 + URL 提交功能
- 用户团队每天提交 20-30 个 URL
- 系统自动 ingest
- 2 个月内可达到 800-1200 所学校覆盖
