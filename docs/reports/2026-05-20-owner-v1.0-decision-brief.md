## 1. 一言サマリー

**コード・パッケージ・Windows v526 side-by-side 動作・CI は release candidate として
green です。** v1.0 を出すために残っているのは技術作業ではなく、
**オーナーの業務判断ひとつ**です。

判断すべきは次の 1 点だけ：

> 「FY2026（令和8）の募集要項はまだ学校側で公開されていない。これを *公開遅延
> (publication lag)* として認め、成熟年 FY2025 の実績を根拠に今 v1.0 を出すか？
> それとも R8 公開シーズンまで待つか？」

---

## 2. なぜこの判断が必要か（事実）

| 指標 | 値 | 意味 |
| --- | --- | --- |
| FY2025（成熟年）strict yield | **60.0%**（600/1000、`ok=true`） | 成熟した年度では目標を満たす |
| FY2026/R8 strict yield | **10.0%**（5/50 canary、上限でも約 39.3%） | R8 要項がまだ世に公開されていない |
| operator-reviewable yield | **100%**（50/50） | 業務員がレビュー可能な範囲は全件カバー |
| コード/パッケージ/CI | green（unit `1901 passed`、PR CLEAN、CI 全緑） | release gate 上の既知コード修正対象なし |

FY2026 が低いのは **EIDP の不具合ではなく、学校が令和8年度の要項をまだ公開していない
という実世界の事情**です。RCA でも「見つかる R8 系 PDF はガバナンス開示・シラバス・
パンフレットで、募集要項本体ではない」と確認済みです。

## 3. 2 つのルート

オーナー決裁欄:

| 選択 | 内容 | 記入 |
| --- | --- | --- |
| ルート A | `publication_lag` 例外を承認して今 v1.0 を出す | yes / no |
| ルート B | R8 公開シーズンまで v1.0 を待つ | yes / no |
| 決裁者 | オーナー氏名 | |
| 決裁日 | YYYY-MM-DD | |

### ルート A — 今 v1.0 を出す（publication_lag 例外）
- オーナーが「R8 はまだ公開されていない。成熟年 FY2025 の 60% 実績を根拠に出す」と承認。
- 加えて業務員 PC で Stage 6 実機 1 サイクルを回し、sign-off を返す。
- → v1.0 タグ可能。**今すぐ動ける。**
- 注意：これは「FY2026 で 60% 達成した」という主張ではなく、「成熟年実績 + 公開遅延の
  明示的受容」での出荷です。R8 公開後の再検証が follow-up 条件として残ります。

### ルート B — R8 公開を待つ
- 学校が令和8年度要項を公開する季節まで v1.0 を延期。
- 公開後に discovery を再実行し、自然に strict 60% 達成 → 例外不要で出荷。
- → 外部イベント待ち。時期は学校側の公開スケジュール次第で、こちらから早められない。

## 4. ルート A を選ぶ場合のオーナー作業（物理的手順）

**ステップ 1 — 例外レコードを承認**
ファイル: `docs/reports/2026-05-19-publication-lag-release-exception-record.md`
次の欄を記入：

| 欄 | 記入内容 |
| --- | --- |
| Status（先頭） | `NOT_APPROVED` → `APPROVED` |
| Decision | `NOT_APPROVED` → `APPROVED` |
| Approver | オーナー氏名 |
| Approval date | 承認日 |
| FY2026/R8 status acknowledged | `yes` |

さらに、レコード内の「Required acknowledgement text」をそのまま承認意思として残す
（FY2026/R8 が 60% 未満であること、本例外は成熟年 FY2025 実績に限定されること、
Stage 6 owner 実機証拠を免除しないこと、を承知している旨）。

**ステップ 2 — Stage 6 実機 1 サイクル + sign-off**
業務員 PC で 1 週次サイクルを実走し、E2E テンプレートに実測値を記入し、
`Owner sign-off` / `業務員 sign-off`（氏名・日付・Decision=yes）を返す。
KPI 行（ship_readiness_rc / strict 自動取得率 / 推定手作業率 / Excel ready 率 /
Excel 整合性）と監査行（manual_action_log 件数 / JSONL outbox 未送信 / audit-flush /
action_id 重複）を埋める。

**ステップ 3 — 検証（開発側が実行）**
オーナーから上記 2 点が返ったら、開発側で：
```
uv run python scripts/verify_stage6_return.py ... --release-exception-reason publication_lag --json
```
を実走し、`ok=true` を確認 → v1.0 タグ。
